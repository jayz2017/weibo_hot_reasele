## 二、问题清单（按严重程度排序）

### 🔴 P0 — 严重问题（运行时 Bug，必须修复）

#### 问题1: `api_server.py` 热榜接口 `await` 同步方法 → 运行时 TypeError

| 项目 | 详情 |
|------|------|
| **文件** | [api_server.py](file:///e:\haochenkeji\weibo_hot_reasele\api_server.py) 第188行、第207行 |
| **问题** | `HotSearchCrawler.execute()` 和 `DataFilter.execute()` 是**同步方法**（返回 `List[HotSearchModel]`），但 API 路由中用 `await` 调用：`raw_data = await crawler.execute()` 和 `filtered = await data_filter.execute(raw_data)`。Python 中 `await` 一个非协程对象会抛出 `TypeError: object list can't be used in 'await' expression` |
| **影响** | `/api/hotsearch` 和 `/api/hotsearch/filter` 两个核心接口**完全无法工作** |
| **方案** | 方案A: 将 `HotSearchCrawler.execute()` 改为 `async def execute()`（内部 HTTP 请求仍同步，但标记为 async 可被 await）；方案B: API 层去掉 `await`，直接同步调用 |

#### 问题2: `api_server.py` 热榜接口对 HotSearchModel 调用 `.get()` → AttributeError

| 项目 | 详情 |
|------|------|
| **文件** | [api_server.py](file:///e:\haochenkeji\weibo_hot_reasele\api_server.py) 第193-199行 |
| **问题** | `HotSearchCrawler.execute()` 返回 `List[HotSearchModel]`（dataclass 对象），但 API 端点用 `item.get('rank', 0)` 对 dataclass 调用 dict 方法。Dataclass 没有 `.get()` 方法，会抛出 `AttributeError` |
| **影响** | 即使问题1修复，`/api/hotsearch` 接口仍会崩溃 |
| **方案** | 将 `item.get('rank', 0)` 改为 `item.rank`，`item.get('word', '')` 改为 `item.word` 等 |

#### 问题3: `api_server.py` `_run_pipeline_async()` 事件循环冲突

| 项目 | 详情 |
|------|------|
| **文件** | [api_server.py](file:///e:\haochenkeji\weibo_hot_reasele\api_server.py) 第280-301行 |
| **问题** | `_run_pipeline_async()` 在 BackgroundTasks 中被调用，内部使用 `asyncio.new_event_loop()` 创建新事件循环。这会在 uvicorn 已运行的主事件循环之外创建隔离循环，导致 Playwright 的异步操作出现状态冲突（Playwright 期望在同一个事件循环中管理 browser 生命周期） |
| **影响** | `/api/pipeline/run` 触发流水线后可能卡死或抛出事件循环相关异常 |
| **方案** | 使用 `asyncio.create_task()` 在主事件循环中直接调度 `pm.run_pipeline()`，避免创建新事件循环 |

### 🟡 P1 — 高优先级问题

#### 问题4: Skill `__init__` 参数签名仍有不一致

当前各 Skill 的构造函数签名：

| Skill | `__init__` 签名 |
|-------|----------------|
| HotSearchCrawler / DataFilter / DataExtractor / StorageManager / ImageHandler | `(self, config: Dict, logger: Logger)` |
| ContentCollector | `(self, config: dict, logger: Logger, *, browser=None)` |
| ArticleProcessor / CommentProcessor | `(self, config: dict, logger: Logger, *, image_handler=None)` |
| **AuthorMonitor** | `(self, config: Dict, logger: Logger = None, *, browser=None, mysql=None)` |
| **Zhibo8MatchScraper** | `(self, config: Dict, logger: Logger = None, *, browser=None, mysql=None)` |

**存在的问题**：
- AuthorMonitor / Zhibo8MatchScraper 的 `logger` 有默认值 `None`，其他 Skill 没有。这破坏了 LSP（里氏替换原则），调用方无法用统一方式初始化
- 类型注解不统一：`config: dict` vs `config: Dict[str, Any]`，`logger: logging.Logger` vs 无类型
- BrowserController 的 `__init__` 没有使用 keyword-only 参数，但它是直接依赖，不需要注入

**方案**: 统一为标准签名 `(self, config: Dict[str, Any], logger: logging.Logger, *, browser=None, mysql=None, image_handler=None)`，logger 不做默认值

#### 问题5: `AuthorMonitor` 和 `Zhibo8MatchScraper` 重复实现导航栏隐藏方法

| 项目 | 详情 |

| **问题** | `AuthorMonitor` 有自己的 `_hide_navigation_bar()` / `_restore_navigation_bar()` 方法（62行），与 `ImageHandler._hide_navigation_bar()` / `ImageHandler._restore_navigation_bar()` 几乎完全重复。且 AuthorMonitor 的方法缺少 user-avatar / avatar 等选择器 |

| **方案** | AuthorMonitor 和 Zhibo8MatchScraper 接受 `image_handler` 依赖注入，统一使用 `ImageHandler` 的方法 |

### 🔵 P3 — 低优先级优化

#### 问题14: `BaseSkill.execute()` 设计问题

| 项目 | 详情 |
|------|------|
| **文件** | [base.py](file:///e:\haochenkeji\weibo_hot_reasele\core\base.py) |
| **问题** | `execute()` 被定义为 `@abstractmethod` 且返回 `Any`，但没有约定是同步还是异步。实际实现中：BrowserController 是 async，ImageHandler 是 sync，HotSearchCrawler 是 sync，DataFilter 是 sync。这导致调用方不知道是否应该 `await` |
| **方案** | 将 `execute()` 统一改为 `async def execute()`，所有同步实现也改为 `async def`（Python 允许 async 函数内部执行同步代码） |

#### 问题15: 缺少 `__init__.py` 中的公共 API 导出

各模块的 `__init__.py` 均为空文件，没有显式导出公共接口，使用者无法通过 `from skills import HotSearchCrawler` 简洁导入

#### 问题16: Pydantic Model 定义但未在路由中严格使用

`api_server.py` 定义了 `ArticleItem`、`CommentItem` 等 Pydantic models，但端点返回时使用 `ResponseModel` 且数据以 dict 嵌套，Pydantic 的类型校验未发挥作用

#### 问题17: 截图目录配置分散

`config.yaml` 中 `zhibo8.screenshot_dir` 和 `paths.screenshot_dir` 分开管理；此外 `ImageHandler` 和 `StorageManager` 分别维护各自的截图目录逻辑

#### 问题18: 缺少统一的 CLI 入口

4 个独立入口 (`main.py`, `author_monitor_main.py`, `zhibo8_main.py`, `api_server.py`)，可以用 `click` 或 `argparse` 子命令统一

#### 问题19: 日志格式手写而不是从 config.yaml 读取

各入口文件手写 `setup_logger("name", level="INFO")`，而 `config.yaml` 中 `logging` 配置未被使用

#### 问题20: `author_monitor_main.py` 中 AuthorMonitor 初始化参数顺序不一致

```python
monitor = AuthorMonitor(config, logger, browser=browser, mysql=mysql)
```
这里传了 `logger` 在第二个位置（有默认值 None），但实际上不需要传位置参数。应该使用 keyword-only 方式。
